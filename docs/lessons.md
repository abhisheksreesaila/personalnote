- 2026-09-30 · Before offering interpretations of a product idea, check what the app already implements (e.g. "expand/shrink" = existing draw.io-style page growth), so questions start from what's built.
- 2026-09-30 · Worktree subagents branch from origin/main, not local main; when local main is ahead, tell builders to rebase onto local main before finishing. Never chain `git commit -a` after a merge that may conflict — it commits the conflict markers.
- 2026-09-30 · A Fabric 7 subclass must set its own defaults in its constructor (`super(); Object.assign(this, X.ownDefaults); this.setOptions(options)`); a `static ownDefaults` alone is silently ignored.
- 2026-09-30 · Never have the client guess a future revision (e.g. in-flight R+1) to save on close — it can overwrite an agent's write; send the last confirmed revision and accept a conflict.
- 2026-09-30 · Builders and reviewers must stop every server, browser and window they start, and never use the app's real port (3137) or the captain's real database; a leftover old server on 3137 made the captain's test open stale code.
- 2026-09-30 · Guard every browser-storage access (localStorage can be missing in WebKit web views) and check frontend changes in a non-Chromium engine; tests/test_webview_smoke.py loads the built app in the system web view with a hidden window.
- 2026-10-02 · Never use broad pkill patterns (e.g. `pkill -f headless`) — other projects' sessions run headless browsers on this machine; stop only the PIDs you started.
- Cleanup deletes only exact paths you created; never `rm -rf` with a glob (a reviewer's `/var/tmp/tmp*/t.db` could have hit other projects' files).
- 2026-10-02 · Take the "before" run of the verify and benchmark scripts from a clean copy of the branch (export it into a scratch folder), never from the tree being edited: a run that overlaps edits fails for the wrong reasons and proves nothing.
- 2026-10-02 · Before removing a library that tests used as their oracle, measure what it does into a fixture (tests/fixtures/fabric-oracle.json) and name the commit that still has the library in the fixture's README, so the tests keep their independent check.
- An engine port needs a feature inventory of the old app (every tool, button, shortcut) checked off before calling parity; four Fabric features (shape tool, Clear all, voice placement, agent flag) slipped through slice-by-slice reviews.
- Test and benchmark runs on the captain's machine are headless (or under a virtual display); never open visible browser windows, never in a loop that respawns them.
- Rendering choices are decided by the in-app comparison on the real Mac, not by headless runs: headless ranked the gesture transform best, the Mac ranked it worst.
- Before merging anything into leafer, run every verify-* script (one at a time), not just the ones the change seems to touch: a CSS-only dock fix broke the IME text check because the test clicked where the dock used to be inert.
- 2026-10-12 · Real-app check scripts must take their ports from the environment: a reviewer running the same script in parallel made the main run fail on a busy port.
- 2026-10-12 · A new capability is added to the existing experience, never as a separate surface that hides existing tools or replaces a default: preview 1's page note dropped the dock, zoom and page growth, and the captain rejected it. Before changing a default, list what the captain loses.
- 2026-10-12 · Real-app checks must try the captain's plainest gestures with the actual mouse: one line of text then an underline under it, a mouse drag to select words. The checks drew circles on a word with a line below it and selected with the keyboard, so preview 2 shipped with both broken.
- 2026-10-13 · A drag target must say yes in `dragenter` as well as `dragover` (Playwright and some web views send `dragover` rarely), and must not rely on `dragleave` (it fires between a row's own children and can carry no position); real-mouse drag checks need a tall window, or the sidebar auto-scrolls under the pointer.
- 2026-10-16 · A builder killed another session's stale server on a shared port while debugging; a busy or stale port means pick another port from the environment, never kill a process you didn't start (repeat of the 2026-10-02 rule). Now enforced in structure: every verify and benchmark script that starts a server calls `assertPortsFree` from `scripts/lib/ports.mjs` and exits 1 on a busy port (it never kills or reuses); set `PN_VERIFY_PORT` to move a script, and new scripts must use the helper.
- 2026-10-17 · The captain's real database was opened again by an agent (F-098 started the API without PERSONAL_NOTE_DB); now enforced: app_paths refuses the default database inside .claude/worktrees/ (tests/test_app_paths.py).
- 2026-10-17 · A drop target's dropEffect must be one the source's effectAllowed lists, or the browser silently cancels the drop (the row said copyMove, the target said link, no drop event came): check every new drop in the real app with a real mouse drag.
- 2026-10-17 · A module imported by the first load and by a lazy chunk (api.js, icons.js, notebook-icon.js) becomes a chunk of its own and costs first-load gzip: hand it to the lazy code as a parameter or use plain fetch there, and read the budget script's first-load number after every such import.
- 2026-10-17 · Anything that compares a stored note with an older copy of it (agent Undo, a merge) must undo the app's page-frame shift first: the app saves a note in its own frame, moving every object by a page width, when content sits past the left or top edge (a note made by the command line does not move). Compare raw coordinates and every save looks like an edit of every object. Real-app checks must press an island chip only after the island has finished gliding to its new size, or the press lands on the canvas beneath (verify-agent-edit.mjs `settled`).
- 2026-10-17 · Settings shows one section at a time (F-102): a check script that reaches a settings control by id must call `showSection(page, id)` from `scripts/lib/settings.mjs` first (and `closeSettings` to leave), or Playwright sees a hidden element and waits out its timeout; new lazy UI brings its CSS in with `?inline` so it counts under the JS budgets, not the first load, and must not `import 'lucide'` (that splits a first-load chunk).
